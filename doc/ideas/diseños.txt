Estrategia A: Separar [HL] en sus propios templates independientes (La más recomendada)
En lugar de intentar meter la memoria dentro de tu plantilla de registros, dejas que el template LD r8, 
r8 use únicamente tus 7 registros reales de 8 bits (lo que te resolverá 49 opcodes automáticos).Para las instrucciones que involucran a [HL], 
creas dos plantillas cortas y específicas:

1. Para leer de la memoria: LD r8, [HL] (Opcodes del tipo 0x46, 0x4E...)

cpptemplate <std::uint8_t CPU::*registro_destino>
int CPU::op_ld_r8_hl() {
    // 1. Obtenemos la dirección de 16 bits combinando H y L con Bit Shifting
    std::uint16_t direccion = get_HL(); 
    
    // 2. Le pedimos el byte real al Bus y lo guardamos en el registro destino
    this->*registro_destino = bus.read(direccion);
    
    // 3. Cuesta 2 M-Cycles (8 T-Cycles) porque leer de la memoria toma más tiempo
    return 2; 
}

2. Para escribir en la memoria: LD [HL], r8 (Opcodes del tipo 0x70, 0x71...)cpptemplate <std::uint8_t CPU::*registro_origen>
int CPU::op_ld_hl_r8() {
    std::uint16_t direccion = get_HL();
    std::uint8_t dato = this->*registro_origen;
    
    // Usamos el método write del Bus (que implementarás en el futuro)
    bus.write(direccion, dato); 
    
    return 2; // Cuesta 2 M-Cycles
}

¿Cómo se mapearía esto en tu constructor?Al separar el comportamiento de la memoria, tu constructor seguirá viéndose sumamente limpio y ordenado. Un fragmento de tu mapeo manual se estructuraría así:cpp// Copia pura entre registros reales (Usando tu plantilla de dos parámetros)
opcode_table[0x40] = &CPU::op_ld_r8_r8<&CPU::B, &CPU::B>; // LD B, B
opcode_table[0x41] = &CPU::op_ld_r8_r8<&CPU::B, &CPU::C>; // LD B, C

// Cuando la tabla te pide [HL], "enchufas" las funciones de memoria que creaste arriba:
opcode_table[0x46] = &CPU::op_ld_r8_hl<&CPU::B>;          // 0x46 -> LD B, [HL]
opcode_table[0x70] = &CPU::op_ld_hl_r8<&CPU::B>;          // 0x70 -> LD [H
